With it shortened to about 0 m or 12 m, physics v2 alone still gives long stretches later in the race. The outcome jumps around with the fade length: 35 m gives a 10.5 s stretch; 40, 60, 75 and 100 m give none. 12 m also fails `tests/wet-review-start.test.ts`. So retuning the AI start is not a real fix.

**Fix:**
- `src/rendering/race-review.ts`: new `REVIEW_START_SLOTS` setting. Close racing stays mid-field; wet following now starts from the back of the grid. With current physics, a back-of-grid start follows a wet car at 29.4–37.5 s and 45.9–54.8 s (also 10.6 s for 6.43 s and 41.2 s for 4.33 s).

- `tests/wet-review-start.test.ts`: new headless regression that replays the exact hosted session. It starts recording 15 s after the green light and requires qualification when sampled every 0.9 s, at four different timing offsets. It also checks that the same session does not qualify with spray removed. It fails for the mid-field start ("expected false to be true") and passes for the back start in about 17 s.
- `docs/production/PHYSICS_MODEL.md`: added the hosted session as a third start-sensitive scenario, with the scan table, so the next start-behaviour change gets re-measured.

**Tests run:**

## fix:aurel-loading

**Worktree:** `/home/user/Experiment-3/.claude/worktrees/wf_d5758f75-0bc-2`
**Branch:** `worktree-wf_d5758f75-0bc-2`. I merged the integration branch first, which fast-forwarded to b509815. The integration branch has since moved to f00a161; none of its new commits touch my files. Nothing pushed.
**Commit:** `7096ec2` fix(render): diagnostics flank readback no longer waits on queued GPU work; 55 grid load budget

**Root cause:** the merges did not make loading slower. This test sits near the 60 s limit on a software GPU, and the test's own diagnostics polling stalled the page for tens of seconds inside that window.

I couldn't get the hosted logs or artifacts (blob storage returns 403), so all evidence is local. I compared a build of 53b6130 (last commit whose shard 7 passed; the test is in the same shard and position in both plans) with b509815, using Mesa llvmpipe, the hosted backend:
- **Same work.** Shader sources compiled before/after the click are byte-identical (246/158). The same 79 programs link during loading. The paused grid draws 1331 calls / 9.41 M triangles in both.
- **Same CPU cost.** Click-to-paused took GPU process 71.7/85.1 s and renderer 10.9/11.2 s at head, against 69.9/90.2 s and 10.9/13.2 s for the old build (two alternating rounds).
- **Worker start is negligible.** A 12-car `Simulation` builds in about 0.1 s in node; the worker module evaluates in 0.6 s in the browser.
- **The candidates in the brief add nothing at load:** catalogue bodies and bikes build lazily, and physics v2, ULTRA, venue kit and career add no load-time work for a Formula grid.
- **Both builds sometimes miss 60 s.** In the real test flow, click-to-paused took 79.6/53.9/77.0 s for the old build and 87.2/56.3/55.0 s for head.

The stall: each `apexDiagnostics()` call reads a pixel back from the player car's flank livery canvas. When that canvas (or the resized copy `TextureBudget` makes of it) lives on the GPU, `getImageData` waits behind all queued GPU work. That blocked the main thread for 18–33 s per load. It also held back the worker's first frame: the worker was ready at 8.4 s but only received its init message at 16.9 s.

**Fix:**
- `car-livery.ts` / `geometry.ts`: flank canvases are created CPU-backed (`willReadFrequently`) and the texture is tagged `cpuReadback`. `texture-budget.ts` keeps the resized copy of a tagged texture CPU-backed too. Readback time during loading dropped from 18.6–32 s to 1 ms. Diagnostics return the same values.
  - Real-flow click-to-paused with this fix was 61.0/38.8/57.7 s. That is better on average but within the run-to-run noise, because the GPU work still has to finish. So this alone may not get the test green.
- `e2e/55`: I raised only the click-to-paused poll from 60 s to 180 s, the same budget as the other cold 12-car tests (53-a61-rival, 32-race-clarity). This is the proof case the rules allow: the measurements above show 60 s was timing the host, not the product. It still requires a real paused grid at tick 0. Every other assertion and timeout is unchanged.

**Tests:**
- New unit tests: the flank canvas is requested as CPU-backed and tagged (`tests/paint-livery.test.ts`); the budget copy is CPU-backed only for tagged textures (`tests/presentation.test.ts`).
- The 26 unit test files that touch the changed rendering modules: 278/278 passed.
- `npm run lint`, `npx tsc --noEmit` and prettier: clean.
- `test:physics` not run, since no simulation code changed.
- Real e2e/55 "Aurel venue ships…" under Mesa on the fixed build: passed twice (3.7 and 4.0 min).
- Temporary probe specs and the temporary Playwright config were removed. The measurement data is in `/tmp/claude-0/-home-user-Experiment-3/c20c3567-05b6-5daa-8126-ea386a6ddfeb/scratchpad/aurel-load/`.
